Brand Portal - Test Workflow Mockup

Multi-tenant business management portal (System 1) plus a public customer storefront. Next.js 16 App Router, TypeScript strict, Tailwind 4, shadcn/ui, Firebase Auth / Firestore / Storage, Zod, Vitest. This page explains the product workflow, what is tested, how, and the exact results so far.

All writes happen server-side (Admin SDK) Tenant = businesses/{id} Access = members/{uid} document only Prices = integer minor units

1. Product workflow (what a tester follows)

Owner journey

1Register/register then verify email
→
2LoginHttpOnly session cookie __session
→
3Onboarding/onboarding 4-step wizard, atomic transaction creates the business
→
4Dashboardlist of my businesses, "Open workspace"
→
5Workspace/b/{id}/overview

Catalogue management (inside the workspace)

6Categoriescreate, edit, reorder, hide, delete (blocked while products exist)
→
7Productsname, category, price, images, description, optional SKU / stock / SEO
→
8ImagesPNG/JPEG/WebP up to 8 MB, first image is the cover
→
9Publishproduct needs an image; store needs the "Store published" switch

Public storefront (no login)

10Home/s/{slug} hero, categories, featured, latest
→
11Category/s/{slug}/category/{c} sort + pagination
→
12Product/s/{slug}/product/{p} gallery, price, stock

Visible only if: store published AND product active AND its category active. Otherwise HTTP 404 (indistinguishable from "does not exist").

3. Architecture in one picture

Browser
  |  pages (RSC)  /b/[id]/*   -- requireWorkspace(id, permission)  --> session cookie -> verifyIdToken/revocation
  |  public pages /s/[slug]/* -- public-store.service (allow-listed fields only)
  |  JSON/multipart API  /api/b/[id]/{categories,products,settings,media}
  v                           CSRF -> session -> size -> Zod -> authorizeMember(members/{uid}) -> rate limit
Server (Next.js route handlers / server components, Firebase Admin SDK)
  |-- services: category / product / media / settings / public-store / onboarding
  v
Firestore  businesses/{id}/{categories,products,media,settings,members,slugReservations}   slugs/{slug}
Storage    businesses/{id}/media/{uuid}.{png|jpg|webp}   (never linked directly; served by app routes)
Images:  /api/b/{id}/media/{mediaId}   (members only)    /api/public/media/{id}/{mediaId}  (only if publicly visible)

5. Test workflow (layers, in the order they run)

1Statictsc --noEmit, ESLint
→
2UnitVitest, no emulator
→
3RulesFirestore + Storage emulators
→
4Integrationreal services + route handlers on Auth/Firestore/Storage emulators
→
5HTTP e2eboots the real Next server, drives it with fetch
→
6Browserreal Chrome, production build, strict CSP, desktop + mobile
→
7Manual / extensionregression on the real project (see prompts)

Commands: npm run typecheck · npm run lint · npm test · npm run test:rules · npm run test:integration · npm run test:e2e · npm run build. Destructive suites refuse to run unless Firebase emulators are active (project demo-brand-portal).
